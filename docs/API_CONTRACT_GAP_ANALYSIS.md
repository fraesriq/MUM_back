# Qué debe resolver el equipo responsable del contrato MUM

**Prioridad: definir quién puede publicar y cómo reconciliar escrituras con resultado incierto.** Las rutas existen, pero ni un token de aplicación acredita a un editor individual ni un error de almacenamiento garantiza que la fila siga intacta. Ambos puntos afectan decisiones de integración antes de cualquier mejora de formato.

Este informe es para responsables de API, seguridad y operación. Para implementar un cliente, use la [guía de integración](API_INTEGRATION_GUIDE.md); para auditar una ruta concreta, consulte [OpenAPI](openapi.yaml) y la [trazabilidad](API_CONTRACT_TRACEABILITY.md). Base del análisis: árbol de trabajo, no un despliegue. [Registro principal](../src/routes/app.js) y [montaje de módulos](../src/routes/index.js): **69 operaciones**, tres de salud/OAuth y 66 de catálogo. Estas últimas se reparten en categorías 5, especies 10, lugares 10, galería 2, contenidos 7, archivos 7, fuentes 5, coordenadas 5 y geografía 15.

## Hallazgos AS-IS, por impacto en decisiones del consumidor

Alta: afecta autoridad de publicación o recuperación de cambios persistentes. Media: puede impedir una integración correcta o inducir un diagnóstico equivocado. Baja: discrepancia acotada que admite una adaptación local. La prioridad no es una afirmación de incidente observado.

| Prioridad | AS-IS y consecuencia | Evidencia verificable |
|---|---|---|
| Alta · A1 · Identidad editorial | La identidad es la aplicación; `catalog:write` habilita gestión, aprobación y limpieza. No hay separación por editor o por tarea en estas guardias. La identidad del usuario y su autorización no se pueden inferir del JWT de aplicación. | [Emisión y sujeto](../src/auth/jwt.service.js), [autorización vigente y herencia](../src/auth/application.middleware.js), [contenidos](../src/modules/contenidos/contenidos.routes.js) y [archivos](../src/modules/archivos/archivos.routes.js). |
| Alta · A2 · Resultado de una baja | `deleteWithCleanup` cambia la referencia en BD antes del borrado remoto. Si falla el borrado o el cierre de la tarea, el cliente puede recibir un error después del cambio. El servicio usa `409` y, en fallos de seguimiento, `503`; el middleware global solo conserva los 4xx: ese `503` interno llega como **`500 {message}`**, a diferencia del `503` directo de `/health`. Repetir la baja no reconcilia el almacenamiento. | [Transacción](../src/modules/archivos/archivos.repository.js), [remove, confirmUpload y processCleanup](../src/modules/archivos/archivos.service.js), [normalización HTTP](../src/middlewares/error.middleware.js). El [catálogo previo](endpoints_catalogo.md) describe el `503` del servicio, no el resultado final de la cadena HTTP. |
| Media · M1 · Clientes OAuth genéricos | El token anuncia `Bearer`, pero v1 lee el JWT sin prefijo en un encabezado propio. Además, la verificación y la consulta de vigencia están en un mismo bloque de manejo de errores: un `401` no distingue credencial caducada de fallo al consultar permisos. Renovar indefinidamente agrava la presión sobre la emisión limitada. | [Controlador OAuth](../src/auth/oauth.controller.js), [middleware de aplicación](../src/auth/application.middleware.js), [limitador de emisión](../src/routes/app.js). |
| Media · M2 · Salud parcial | `/health/live` indica que el proceso responde y `/health` consulta la BD; la configuración R2 se valida de forma diferida. Un `200` de salud no acredita firma, transferencia, CORS del bucket ni migraciones aplicadas. | [Comprobaciones de salud](../src/routes/app.js), [configuración R2](../src/config/r2.js), [firma y comprobación de objeto](../src/storage/r2.service.js), [migración de durabilidad](../migrations/20261121_archivo_r2_durability.up.sql). |
| Media · M3 · Actualización de especies | El `PUT` a una especie no es un parcial general: `updateEspecieSchema` conserva `slug` y `nombre_comun` obligatorios. En lugares esos campos equivalentes sí pasan a opcionales. Un formulario de edición que solo envía el campo cambiado puede funcionar para lugares y fallar para especies. | Esquemas de [especies](../src/modules/especies/especies.validation.js) y [lugares](../src/modules/lugares/lugares.validation.js). |
| Media · M4 · Confirmación expirada | El primer control de `confirmUpload` incluye la vigencia para una autorización sin confirmar: una ya vencida puede devolver `403`. Si vence durante el procesamiento hay ramas `409`. En cambio, una confirmación consistente ya completada puede devolver el registro existente, también con `201`. No hay correspondencia exclusiva entre expiración y un único estado HTTP. | `grantIsValid`, `confirmUpload` en el [servicio](../src/modules/archivos/archivos.service.js); resultado `expired_grant` en el [repositorio](../src/modules/archivos/archivos.repository.js); [controlador](../src/modules/archivos/archivos.controller.js). |
| Media · M5 · Envolturas de error | Según el punto de rechazo se obtiene `error_description`, `error` con `message`, `details[]` por campo o solo `message`; el último no lleva código de dominio estable. Un cliente que interpreta cualquier `400` como error Zod pierde el diagnóstico de negocio. | [Validación](../src/middlewares/validate.middleware.js), [OAuth](../src/auth/oauth.controller.js), [manejo global](../src/middlewares/error.middleware.js). |
| Baja · B1 · Filtro sin efecto | `GET /contenidos/aprobados` comparte el esquema que acepta `estado`, pero la consulta pública fija `aprobado`. El parámetro aceptado no cambia qué estados se muestran. | [Rutas](../src/modules/contenidos/contenidos.routes.js), [listQuerySchema](../src/modules/contenidos/contenidos.validation.js), [findAllAprobados](../src/modules/contenidos/contenidos.repository.js). |
| Baja · B2 · Nombre de ficha reservado en la práctica | Los esquemas de escritura admiten el texto `gestion` como slug, pero el segmento está ocupado por el listado de gestión antes del detalle por slug. El enlace público a una ficha así nombrada no identifica la ficha. No se comprobó que haya filas afectadas. | Orden de registro de [especies](../src/modules/especies/especies.routes.js) y [lugares](../src/modules/lugares/lugares.routes.js); esquemas citados en M3. |

**Media · M6 · Registro de errores del analizador.** AS-IS: el [manejador global](../src/middlewares/error.middleware.js) escribe el objeto de error. En una comprobación local con datos sintéticos, un error de análisis incluía contenido de la solicitud en el registro. Esto no demuestra que haya secretos en registros de producción. El cuerpo HTTP del error y el registro del servidor son superficies distintas.

## TO-BE: acciones propuestas, no garantías actuales

| Hallazgo | Responsable sugerido y criterio de cierre |
|---|---|
| A1 | Producto y seguridad: decidir si edición, aprobación y limpieza requieren identidades o permisos distintos. Mientras tanto, mantener escritura detrás de un backend con control de usuarios. Antes de abrir gestión a terceros, acordar una matriz de permisos y comprobar tanto aceptación como denegación por operación. |
| A2 y M4 | API y operación: acordar cómo informar referencia eliminada, limpieza pendiente y autorización vencida sin revelar datos internos. Probar el resultado **HTTP** con dependencias simuladas, incluyendo referencia ya eliminada y confirmación repetida. Documentar qué debe releer el cliente y cuándo interviene operación. |
| M1 y M5 | API: conservar compatibilidad con el encabezado actual; publicar respuestas distinguibles por máquina y un ejemplo por familia. Probar una lectura con el adaptador consumidor y comprobar que un error persistente no produce un bucle de renovación. |
| M2 | Operación: separar señales de proceso, BD y almacenamiento en la verificación del despliegue. Registrar por ambiente la vigencia y el límite aprobados, sin publicar valores sensibles ni asumir que los valores predeterminados están activos. |
| M6 | Seguridad y operación: registrar campos permitidos en vez del error íntegro y verificar la redacción con datos sintéticos; no registrar cuerpos, credenciales ni enlaces firmados. |
| M3, B1 y B2 | Catálogo: decidir campo por campo la semántica de `PUT`, filtros admitidos y segmentos reservados. Antes de restringir entradas, evaluar compatibilidad con datos y clientes existentes; fijar lo decidido en esquema, prueba de ruta y contrato en el mismo cambio. |

## Qué respaldan las pruebas y qué sigue abierto

**Evidencia de prueba** significa que se inspeccionó un caso existente, no que se ejecutó o que pasó en este trabajo. El registro HTTP, las validaciones, los servicios y las proyecciones SQL establecen el comportamiento descrito; por sí solos no certifican el ambiente.

|---|---|---|
| Lectura con credencial de aplicación | [Pruebas de autenticación](../test/auth.test.js): parser Basic, encabezado dedicado, vencimiento y audiencia del JWT, respuesta a credencial inválida. [Pruebas de catálogo](../test/catalog.test.js): herencia de escritura sin herencia inversa. | Credenciales o permisos de algún cliente real, política del proxy desplegado o disponibilidad del emisor. |
| Borrador → aprobación → vista pública | `createContenidoSchema` fija el estado por defecto, el controlador devuelve `201`, el repositorio relee `id_contenido` y la vista pública selecciona filas aprobadas.
